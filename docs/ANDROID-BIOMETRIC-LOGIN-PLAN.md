# Android 指纹登录方案

日期：2026-10-16。状态：方案归档，待 Android 业务页面和设置页完成后实施；当前未实现。

## 1. 目标与边界

按用户确认的流程：首次邮箱登录 → 设置中主动开启 → 完成系统指纹验证 → 开启成功 → 退出账号后仍可选择指纹重新登录。

参考支付宝公开的本地生物验证与账号授权思路，采用 Android 系统认证和设备密钥签名。不接入支付宝账号、支付接口或 IFAA 商业服务；不宣称复现支付宝未公开的内部实现。

- 生物特征由手机系统比对，循形不采集、保存或上传指纹图像、特征、指纹编号。
- 绑定对象是“账号 + 当前安装的设备凭据”，不是某一枚指纹。开启时已录入且符合强度要求的其他指纹也可能通过认证。
- 第一阶段只允许强生物识别授权密钥，不开放弱人脸或锁屏 PIN 作为该入口的替代；邮箱始终可用于恢复。
- 标准 API 按强度限制认证方式，不能在所有手机上保证只出现指纹。实际界面根据能力使用“指纹登录”或“生物识别登录”，不向具备其他强认证方式的设备承诺单枚指纹绑定。
- 本方案是退出后的重新登录，不是 App 锁。已有有效会话仍按现有规则自动恢复，不增加每次启动、后台返回都验证的步骤。
- H5 不在此次实施范围；也不将设备私钥或绑定记录同步到其他手机。

## 2. 页面与交互

### 设置入口

路径：我的 → 设置 → 账号与安全 → 指纹登录。具体导航沿用未来设置页的设计，不提前创建占位页面。

显示状态：未开启、正在开启、已开启、不支持、未录入、需重新开启。持久化开关状态须以本机密钥可用性与服务端绑定状态共同确定，不能仅依赖一个布尔值。

开启前就地说明：

> 开启后，可在本机通过指纹登录当前账号。手机中已录入的有效指纹均可能用于登录，请确保仅录入你信任的指纹。

用户开启时：

1. 检查强生物识别、录入情况及锁屏条件；未录入时提供前往系统设置的入口。
2. 校验近期邮箱认证。刚通过邮箱登录的用户直接继续；若认证已超过建议的 5 分钟窗口，先完成邮箱验证。仅持有旧 Token 不足以新增长期登录凭据。
3. 获取注册挑战，创建当前账号专用的 Keystore 签名密钥。
4. 弹出系统验证窗口，说明“为循形开启指纹登录”。使用 CryptoObject 授权签名。
5. 将公钥与注册挑战签名交给后端；后端确认成功后才展示“已开启”。

取消、识别失败或网络失败时保持未开启；清理未确认的临时密钥。请求超时造成结果未知时，查询注册状态再决定重试或清理，不盲目显示成功。注册重试按同一请求标识幂等处理。

### 登录入口

- 未绑定：保持邮箱验证码为默认入口。
- 已绑定且密钥可用：显示脱敏邮箱、“指纹登录”和“使用邮箱登录”；不要从手指推断或自动切换账号。
- 用户主动点击后，获取登录挑战 → 系统验证并签名 → 后端验证 → 签发新的 AuthSession → 沿用现有安全存储进入应用。
- 成功前不展示账号业务数据；取消后停留登录页，不自动重新弹窗。
- 生物识别失败不发送邮箱验证码，不触发注册，也不把客户端“验证成功”布尔值直接作为服务端登录依据。
- 第一阶段每个 App 安装仅保留一个账号的快捷登录绑定。切换账号需明确移除旧账号的本机快捷登录凭据，再为新账号开启；其他设备的绑定不受影响。

### 退出、关闭与恢复

| 操作或情况 | 当前会话 | 设备登录凭据 |
| --- | --- | --- |
| 普通退出登录 | 按现有接口撤销并清除本机会话 | 保留，可以指纹重新登录 |
| 设置中关闭指纹登录 | 保持当前会话 | 撤销服务端绑定，删除本机密钥与账号提示 |
| 登录页“移除此账号” | 保持退出状态 | 删除本机密钥与提示；服务端记录通过已认证的管理流程撤销 |
| 新增指纹、密钥失效或移除锁屏 | 不静默创建新绑定 | 标记需邮箱登录后重新开启 |
| 指纹暂时锁定、用户取消 | 不改变 | 保留绑定，提供邮箱登录 |
| 卸载、清除数据或更换手机 | 本机会话不可恢复 | 新设备重新邮箱登录并开启 |
| 找回密码、账号禁用或全局安全撤销 | 按既有安全策略处理 | 同时撤销关联快捷登录资格，不能用旧密钥绕过 |

普通退出后仍可指纹登录，是本功能的明确产品规则。退出提示中写明“本机已开启指纹登录，退出后仍可使用；可在账号与安全中关闭”。不为普通退出增加重复确认。

关闭绑定需要网络确认；网络失败不假装已完成服务端撤销，可提供“移除本机凭据”，并说明服务端设备记录需联网后管理。删除私钥即停止本机签名能力。

## 3. 技术设计

### Android

- 使用 AndroidX Biometric 的生产稳定依赖，实施时重新核对版本、更新 version catalog 与锁文件；不为此引入实验性 Compose 生物识别 API。
- 使用 Android Keystore 的 P-256 签名密钥，签名算法 SHA256withECDSA；服务端统一约定公钥 SPKI 格式、签名 DER 格式及 Base64URL 编解码。
- 私钥不可导出，每次签名要求系统强生物认证，配置生物录入变化使密钥失效；按 API 26–29、30+ 分支适配认证参数，实际以 canAuthenticate 和真机密码操作结果为准。
- 使用 BiometricPrompt.CryptoObject(Signature) 授权真实密码操作。采用稳定 AndroidX 方案时评估将当前 ComponentActivity 调整为 FragmentActivity，并回归现有 Compose、ViewModel 和生命周期行为。
- 签名密钥与现有 AES 会话加密密钥使用不同 alias；普通退出只清除会话，不删除快捷登录密钥。
- 绑定提示与 credentialId 按账号、应用包及 dev/prod 环境隔离，存于不参与备份的私有存储；不使用 IMEI、硬件序列号作为凭据。
- 取消、暂未授权、永久失效分别建模；不能沿用当前 SessionStore 将所有密码学异常视为损坏并删除数据的处理方式。
- 账号切换、旋转、重复点击和系统验证窗口返回须保持单次操作语义；离开页面取消未完成的认证。

### 服务端挑战与验签

设备密钥独立于 refreshToken，普通退出撤销旧会话不会撤销设备绑定。服务端通过绑定记录解析账号；客户端提交的邮箱或 userId 不能决定最终登录身份。

每次注册或登录下发密码学安全随机挑战（建议至少 32 字节随机量，120 秒有效）。服务端保存挑战与用途、绑定、环境和过期时间的关联；客户端签名服务端下发的完整规范化 payload 字节，不自行拼接待签字符串。

payload 须绑定协议版本、业务用途、服务端受众/环境、挑战 ID 与随机量；注册同时绑定用户与待注册公钥摘要。登录与注册挑战不能互用，dev/prod 不能互用。

服务端校验签名、有效期、绑定启用状态、用户状态与账号安全版本；挑战消费和新会话签发须防并发重放。认证失败限流，外部错误不暴露账号是否存在。登录成功复用现有 AuthSessionService 的签发、撤销和后续续期机制。

签名可证明持有对应私钥；没有额外硬件证明链时，服务端不能仅凭签名独立证明发生了真实指纹扫描。第一阶段依赖 Android Keystore 与系统认证约束，不把它标称为支付级认证；如以后需要设备可信证明，再独立评估 Key Attestation 与厂商兼容性。

## 4. 拟定接口与数据

以下为实施前接口草案，不代表已有接口。

| 接口（相对 /api/v1） | 认证要求 | 用途 |
| --- | --- | --- |
| POST auth/device-credentials/registration-options | 当前有效会话 + 近期邮箱认证 | 返回注册 ID、挑战 payload、有效期 |
| POST auth/device-credentials/registration-verify | 同上 | 提交公钥、挑战 ID 和签名，创建绑定 |
| POST auth/device-credentials/login-options | credentialId，限流 | 返回一次性登录挑战 |
| POST auth/device-credentials/login-verify | 挑战签名 | 验证后返回现有格式的 AuthSession |
| GET auth/device-credentials | 当前有效会话 | 查询绑定状态及设备记录，不返回密钥秘密 |
| DELETE auth/device-credentials/:id | 当前有效会话，校验所属账号 | 关闭本机或撤销指定设备绑定 |

新增 DeviceCredential：id、userId、publicKey、算法、应用/环境作用域、设备展示名、账号安全版本、createdAt、lastUsedAt、revokedAt。设备展示名不是安全依据。

新增短期 AuthChallenge：id、用途、credentialId 或注册关联、payload/摘要、expiresAt、consumedAt。近期邮箱认证须由服务端可信的认证记录或短期专用授权证明承载，不能由客户端提交时间戳。挑战存储和消费必须支持多实例部署。

不保存指纹、不保存可复用密码、不把 refreshToken 当作永久指纹凭据。指纹认证取得新会话不重复勾选已接受的同版本协议；协议版本升级时走统一确认规则。

## 5. 与当前工程的衔接

- core:model / core:domain：添加能力检查结果、绑定状态、注册与挑战登录契约，领域接口不暴露 Android CryptoObject。
- core:session：实现独立设备密钥管理与签名适配；保留现有会话 AES 加密职责。
- core:network / core:data：新增接口 DTO、挑战编排与异常映射；成功登录复用现有安全保存逻辑。
- feature:auth：加入已绑定账号的快捷登录入口和邮箱回退；设置页面消费同一绑定状态契约。
- app：装配系统验证宿主、导航与生命周期；不把指纹逻辑散落在 Composable 内。
- api / Prisma：新增凭据、挑战及迁移，扩展账号安全撤销路径；H5 继续使用现有登录，不被强制改造。

当前代码检查依据：KeystoreSessionStore 未要求生物认证；MainActivity 在 ON_START 自动恢复会话；DefaultAuthRepository 维护内存会话；现有 auth/logout 撤销 refreshToken 关联会话。因此独立设备凭据是满足“退出后仍能指纹登录”的必要改动，不复用已撤销会话绕过退出。

## 6. 实施顺序与验收

安排在 Android 业务页面、我的/设置导航可用之后。实施前先完成设置入口、开通/失败/关闭状态及登录入口的可编辑设计，再修改页面代码。

1. 确认接口契约、近期邮箱认证证明和账号安全撤销规则。
2. 完成服务端绑定、挑战、验签及必要数据库迁移。
3. 完成 Android 密钥与系统验证接入，再连接设置和登录页。
4. 完成接口、安全规则、状态机与页面测试，再做设备验收；不以模拟指纹通过替代真实硬件验证。

必测：

- 首次邮箱登录开启成功；取消或失败不显示已开启；网络结果未知时可恢复查询。
- 普通退出确实撤销旧会话，随后通过签名获得新会话，不复用旧 Token。
- 挑战重复、过期、用途替换、账号替换、环境替换、签名错误及并发消费均被拒绝。
- 关闭后不能再登录；找回密码、全局安全撤销后旧绑定不能创建新会话。
- 设备无指纹、未录入、暂时锁定、系统取消均可回退邮箱；失败不自动发送邮件。
- 多枚原有指纹行为符合系统规则，新增指纹导致绑定失效并要求重新开启。
- 旋转、切后台、系统弹窗返回、重启进程、清除数据、重新安装及账号切换。
- 至少验证当前小米真机，并覆盖旧 Android 兼容分支与深浅色、大字体；用户实际触碰传感器完成验证。

## 7. 官方参考与证据边界

- [支付宝指纹服务协议](https://render.alipay.com/p/yuyan/180020010001201259/agreement/zw.htm)：指纹由设备系统保存和比对，支付宝不保存；提醒其他人录入指纹的风险。
- [IFAA 本地免密认证方案](https://vip.iifaa.org.cn/specifications.htm)：账号、设备与服务相关密钥，公钥上送，私钥本地保护，验证后签名。
- [Android 生物识别与 CryptoObject](https://developer.android.com/identity/sign-in/biometric-auth)：能力检测、强度选择、密码操作绑定与版本限制。
- [Android Keystore 参数](https://developer.android.com/reference/android/security/keystore/KeyGenParameterSpec.Builder)：认证约束和生物录入变更失效配置。

本文参考公开路线，不代表已验证支付宝特定机型内部实现；标准 Android 能力不承诺只绑定开通时那一枚指纹。本轮无新增接口、迁移、设置页面、依赖、设备操作或上线部署。
