# 减少日常填写：实施计划

## 基线

承接「减少用户手动填写内容」任务及本地撸铁记观察报告。开发前将既有草稿、常用餐、上次成绩、首页训练卡与安装文档提交为 `6b93eed`。基线通过 `pnpm check`、H5/API 构建及 200 项回归测试；测试的 HTTP 监听在允许本机端口的环境完成。

## 第一批：本次开发范围

1. 完成可编辑 Figma 流程设计：现成训练方案、当前动作逐组执行、休息/暂停、整餐录入与确认。
2. 扩充常见力量动作和居家/健身房模板，保留既有动作及模板 ID；可直接开始，不要求先另存模板。首次不猜重量。
3. 有效历史成绩自动预填；保留手填、已完成组、恢复草稿。失败可重试，不阻挡训练。
4. 当前动作展开，其余收起；已完成动作自动排后，保持保存时的原动作顺序。勾选完成触发可关闭的自动休息；提供跳过、加减时间和暂停/恢复。按时间戳计时，页面重新进入恢复计时状态。
5. 名称、手填时长、默认休息等收进补充设置，正常路径自动计时。
6. 饮食主入口为一句话、拍照和常用餐；文本分析只生成待确认建议。失败仍可直接记录原文，热量未知保持空值；手动、食品库和最近记录继续可用。
7. 检查格式、类型、构建、回归和隔离浏览器流程；交付代码、验证证据和手机验收清单。

## 后续批次

- 第二批：营养素快照与目标、训练容量和肌群统计、月历排期、自定义动作。
- 第三批：报告/标签识别、AI 计划、补剂、后台与锁屏提醒、导出、模块个性化。

## 数据契约

- 历史成绩是建议，不能自动标记为已完成；自动填入须匹配动作 ID 和单位。
- 草稿按当前账号与模板隔离；暂停时间从实际时长中扣除，休息时间属于训练时间。
- 饮食 AI 分析不写入记录，确认并保存才写入；保留零与未知的区别，不用模拟固定菜谱伪装文本识别。
- 本批不调用真实账号的外部 AI，不操作手机，不自动发布线上服务。

## 完成与验证

- 已按顺序完成 [Figma：22 · 减少填写](https://www.figma.com/design/Ct4AworB8fYBPjpSVwWbRW?node-id=111-16)，再实现页面。MCP 额度不足，使用 Codex 内置浏览器导入 SVG；已检查文字层（Inter）、四个矢量画面与完整截图。这是可编辑的固定布局流程稿，未制作可播放原型或变量/组件绑定。源 SVG 与 Figma 截图在本目录。
- 动作库现为 20 个动作、10 个预设模板，旧 ID 保留。新增中文摘要自行编写，动作外部参考为 [ACE 动作库](https://www.acefitness.org/resources/everyone/exercise-library/)；没有复用竞品或 ACE 图片。模板可按居家/健身房筛选。
- 训练自动读取有效历史并预填。首次预设负重动作的实际重量保持待填写状态；徒手为 0，个人模板保留已配置值。仅验证、提交完成组，未练的组可以保持空白。
- 当前动作展开、完成动作排后；排序只改变展示，提交仍保留原动作顺序。完成后可自动休息，支持加减 15 秒、跳过和独立暂停。训练暂停扣除实际时长，训练和休息状态随草稿恢复。名称、手填时长与自动休息开关收进补充设置。
- `POST /ai/food-text` 复用既有 AI 配置，支持 chat/responses 的纯文本内容，不携带图片，不调用存储解析。没有真实 AI 配置时明确失败，不以固定模拟餐食充当分析结果。生成建议后用户确认才加入，修改名称清除旧估算，也可放弃建议。空热量保持未知，真实零热量保持 0；同时修正既有识别 schema 的 required 字段与 null 被数值转换成零的问题。
- 一句话描述、待确认结果均进入账号隔离的本机草稿。可绕过 AI 直接记录原文；超过食物名称长度的原文完整放入备注，不静默丢弃已有备注或长文本。食物明细在有内容时出现，份量/热量默认收起；拍照、常用餐、食品库、最近和手动入口保留。
- `pnpm check`、生产 API/H5 构建、207 项回归测试通过。原有 UiInput 属性顺序警告与趋势页大分包提示保留；构建关闭 source map 上传。
- 内置浏览器使用真实 Vue 页面及隔离内存 API，验证历史自动预填、手填保护、完成动作排后、自动休息、加时/暂停/刷新恢复、只提交完成组、首次重量未填不允许完成、整餐确认后提交、未知热量、描述草稿恢复、AI 失败直接记录与保存后清理草稿。390px 训练与 320px 饮食/模板页面无横向溢出。实现截图在本目录。临时验收入口已删除，未请求真实账号或外部 AI。
